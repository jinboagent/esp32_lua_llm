## Fix Details

### B1 — Data race on script flags (`script_mgmt.c`)
- **Root cause**: `s_script_loaded`/`s_script_running` were plain `bool`;
  CLI task writes them, the pipeline task reads `script_is_running()` —
  same race class as the already-atomic `s_running`/`s_scanning`.
- **Fix**: `atomic_bool` + `atomic_load`/`atomic_store` at every site
  (declaration, `script_upload_end`, `script_run`, `script_stop`, both getters).

### B2 — PM activity-lock failure silently degrades (`power_mgmt.c`)
- **Root cause**: on `esp_pm_lock_create` failure, `power_init` printed a
  line, returned 0, and still enabled light sleep — `power_hold_activity`
  became a no-op, so the SoC could light-sleep mid-scan and drop console
  TX output with no visible signal.
- **Fix**: fail safe — set `sleep_enabled = false`, apply the awake policy,
  log prominently, and return `-1` so `app_main` surfaces a WARNING.

### B3 — `bridge_init()` never called (`main/main.c`)
- **Root cause**: the bridge worked only by static zero-init coincidence.
- **Fix**: explicit `bridge_init()` in the init chain (after the Lua
  engine) with the standard WARNING pattern; `bridge_if.h` included.

### B4 — Pool allocator accounting drift (`lua_port.c`)
- **Root cause**: the soft-limit guards in `s_lua_alloc` checked the raw
  `nsize`, while accounting added the aligned `blk->size` — `ctx->used`
  drifted past the limit over many cycles (hard limit stayed correct).
- **Fix**: compute the aligned size once and use it in both the fresh-alloc
  and resize guards.

### B5 — `pipeline_get_stats` snapshot (accepted)
- Single-writer advisory counters; a torn snapshot only affects a STATUS
  display transiently. Adding a lock to the per-advertisement hot path is
  not worth it. Documented at the function.

### B6 — `lua_engine_deinit` race closed at the CLI (`cli_commands.c`)
- **Root cause**: deinit deletes the engine mutex; a concurrent pipeline
  hook/lock waiter could hit the window between unlock and delete.
- **Fix location rationale**: the guard lives in the CLI (`LUA DEINIT` →
  `-911 "stop scanning and scripts first"`), not in `lua_port.c` — the CLI
  already links both `ble` and script APIs, while a lua→ble dependency
  would create a circular component dependency (`ble` already links `lua`
  for pipeline hooks). This turns the documented "don't deinit while
  scanning" convention into an enforced state guard.

### B7 — Dedup sentinel collision (`ble_scan.c`)
- **Root cause**: `esp_timer_get_time()` starts at 0 at boot; an entry
  recorded at exactly 0 µs would read as an empty slot.
- **Fix**: `now_us = esp_timer_get_time() + 1` — recorded timestamps are
  always ≥ 1, ordering is unaffected.

## Lessons learned

- CMake caches silently break when the active ESP-IDF version changes
  between sessions — a cross-version cache mismatch looks like a code
  failure but isn't; delete `build/` and reconfigure.
- Concurrency fixes belong at the layer that owns both dependencies: the
  B6 guard went into the CLI because component dependency direction
  forbade it in the Lua engine.
