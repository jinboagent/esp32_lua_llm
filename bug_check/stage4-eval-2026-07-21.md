## 二、Bug 发现 — F4.1 CLI Commands

### 🔴 严重 (2 个)

#### B-S4-1. `process_command` 无 NULL 指针检查 — 传入 NULL 即崩溃

**文件**: `main/main.c:17`
**影响**: 调用 `process_command(NULL, ...)` → `strcmp(NULL, "STATUS")` → C 未定义行为 → 崩溃

```c
static void process_command(const char *cmd, char *response, uint16_t response_len) {
    if (strcmp(cmd, "STATUS") == 0) {  // ← 未检查 cmd == NULL
```

所有其他模块 API 都检查 NULL 指针，唯独 CLI 命令解析器不检查。

---

#### B-S4-2. CLI 和 Pipeline 双任务无锁访问 `filter engine`

**文件**: `main/main.c` + `scan_pipeline.c`
**影响**: filter rule 数组并发读写 → 损坏

```
app_main 任务: FILTER ADD/CLEAR → filter_add_rule/clear → 修改 eng->rules[] + eng->rule_count
Pipeline 任务: filter_evaluate → for (i < eng->rule_count) → 遍历 eng->rules[]
```

`FILTER ADD` 期间 `filter_add_rule` 写入 rule 结构体和 `rule_count++`，pipeline 可能读到半写入的 rule。`FILTER CLEAR` 期间 `filter_clear` 用 `memset` 清零所有 rule 同时 pipeline 遍历。

4. **State machine 缺失** — 所有 4 个阶段 Spec 都引用的状态机在 CLI 层完全未实现。
