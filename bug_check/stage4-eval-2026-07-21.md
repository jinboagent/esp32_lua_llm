## 2. Bug Findings — F4.1 CLI Commands

### 🔴 Critical (2)

#### B-S4-1. `process_command` has no NULL pointer check — passing NULL crashes immediately

**File**: `main/main.c:17`
**Impact**: calling `process_command(NULL, ...)` → `strcmp(NULL, "STATUS")` → C undefined behavior → crash

```c
static void process_command(const char *cmd, char *response, uint16_t response_len) {
    if (strcmp(cmd, "STATUS") == 0) {  // ← no check for cmd == NULL
```

All other module APIs check NULL pointers; only the CLI command parser does not.

---

#### B-S4-2. CLI and Pipeline access the `filter engine` from two tasks without a lock

**File**: `main/main.c` + `scan_pipeline.c`
**Impact**: concurrent read/write of the filter rule array → corruption

```
app_main task: FILTER ADD/CLEAR → filter_add_rule/clear → modifies eng->rules[] + eng->rule_count
Pipeline task: filter_evaluate → for (i < eng->rule_count) → iterates eng->rules[]
```

During `FILTER ADD`, `filter_add_rule` writes the rule struct and does `rule_count++`; the pipeline may read a half-written rule. During `FILTER CLEAR`, `filter_clear` zeroes all rules with `memset` while the pipeline is iterating over them.

## 4. Bug Findings — F4.3 Power Management

### 🔴 Entirely unimplemented — 0%

| Required File | Status |
|-----------|:----:|
| `interfaces/power_if.h` | ❌ |
| `firmware/components/power/power_mgmt.c` | ❌ |
| `power_init()`, `power_enable_sleep()`, `power_get_current_ma()` | ❌ |
| `power_state_t`, `power_config_t` | ❌ |

**0 lines of power management code** — no light sleep, no USB suspend detection, no current estimation, no wakeup mechanism. The device runs at full speed continuously.

The pipeline does not even yield when idle (`scan_pipeline.c` busy-loops with `vTaskDelay(50)`), with no consideration at all for power consumption.

### Architectural Issues

1. **CLI is not componentized** — the Spec defines `firmware/components/cli/cli_commands.c` + `interfaces/cli_if.h`; in reality the CLI is embedded in `main/main.c`. Zero reusability and testability.
2. **Bridge does not exist** — `script_mgmt.c` provides the storage functionality but lacks the text-line protocol, sandbox scanning, and upload interruption handling.
3. **Power does not exist** — a completely new implementation is required.
4. **State machine missing** — the state machine referenced by all 4 stage Specs is entirely unimplemented at the CLI layer.
