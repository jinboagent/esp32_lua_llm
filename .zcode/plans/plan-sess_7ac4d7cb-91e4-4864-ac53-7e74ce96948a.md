# ASCII-Chart Registry + Catalog + Update-Checker (dev branch)

**Goal:** every ASCII chart in the repo gets an ID, a registry row, an embedded copy with a simple explanation and reading/maintenance instructions, and a mechanical way to detect "changed since last review" / "obsolete" / "orphaned" — your idea, made executable.

## Design (decisions)

- **ID = `CH-<file-slug>-<NN>`**, one per chart *site* (location-composed, as you proposed). A `master` column links duplicate copies to one canonical chart (e.g. `CH-assist-py-01 master`, `CH-assist-md-01 alias→`). Renamed file → update the location column; the ID keeps its origin hint.
- **Update check = hash + rev.** The registry stores a short SHA of each chart block + `verified` date. The checker recomputes hashes: mismatch → `MODIFIED since review`; marked chart without row → `ORPHAN`; row without chart → `GONE`.
- **Frozen-copy policy:** master charts live in *maintained* sites (README, harness specs, host_app docstrings, firmware/components/ble/README, docs/diagrams html). Copies in `docs/feature-proposal-*`, `docs/archive/**`, `status/archive/**`, `docs/templates/**`, `docs/tostudy.md` are `frozen-proposal` / `historical` / `template` and exempt from the checker — point-in-time records, never maintained.
- **Scope:** dev branch only (`Lua_tool_extension_dev`). Release branch untouched — the registry is development-process meta; its 5 chart files are registered as masters on dev.

## Deliverables

1. **`docs/chart-registry.zcode.md`** — the registry + catalog (author-tagged per your convention), three parts:
   - **Policy section:** ID scheme, statuses (`current` / `stale` / `historical` / `frozen-proposal` / `template`), the update rule ("change a chart → paste new snapshot + bump rev+date+hash in the registry → run the checker"), exempt paths.
   - **Tracking table** (machine-parsed by the checker; one row per SITE, ~35 rows): ID, master/alias, status, location `file:lines`, style, feature link, verified date, sha8, rev.
   - **Catalog — ALL charts extracted, 27 sections** (one per distinct chart, keyed by its master ID). Each section contains exactly what you asked for:
     - the **chart itself** (extracted, in a fenced code block — the last-verified snapshot);
     - a **simple explanation** (2–3 plain sentences: what it shows);
     - **how to read it** (legend: arrows, box types, the dashed simulation loop, PUSH vs PULL planes…);
     - **instructions**: which code/feature it must stay in sync with ("when you change X, update this chart") + its duplicate sites (master/aliases);
     - status line (current / stale / frozen / historical + verified date).
   - Includes the 2 confirmed-stale charts (flagged) and all historical/frozen charts — so the catalog is the single place to *read* every chart in the project.
2. **`scripts/check_charts.py`** — stdlib-only, self-contained (house style):
   - Scans tracked text files for chart-shaped blocks (≥3 consecutive lines of box-drawing / `+----` / tree chars), collects `CH-…` markers, parses the tracking table.
   - Reports: `MODIFIED` (hash mismatch), `ORPHAN` (unmarked chart in a non-exempt path), `GONE` (marker vanished), `STALE` reminders; advisory (report + exit code; can be promoted into the test suite later).
   - Exempt paths built in: `docs/archive`, `status/archive`, `docs/templates`, `docs/tostudy.md`, build/vendor dirs.
3. **Markers inserted** at the ~14 maintained sites (one invisible comment line per chart: `<!-- CH-readme-01 rev1 2026-09-26 -->` in md, `# CH-assist-py-01 rev1` in Python). No chart content changed in this step.
4. **Refresh the 2 confirmed-stale charts** (content fix, then registered as current, snapshot pasted into the catalog):
   - `harness/00-global-context/project_overview.md:11-31` — add F2.4 conn plane, cli/bridge/power modules, three host tools.
   - `harness/01-features/stage4-integration/feature_cli_commands.md:26-31` — note that CONN and PACK families run outside the IDLE/SCANNING/SCRIPT_RUNNING machine (CONN's own state diagram already exists in `firmware/components/ble/README.md`).
5. **Convention adoption:** a short "Chart management" note in `CLAUDE.md` + `AGENTS.md` (dev) pointing to the registry and checker so agents follow the bump-rev rule.
