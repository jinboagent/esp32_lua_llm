## 🔄 Design Redirection (CRITICAL — Read Before Continuing Implementation)

### Problem Identified
The `design_patch.md` file identified that we've been **reinventing the wheel** for multiple modules when ESP-IDF already provides battle-tested alternatives. This is the root cause of the -104 bug (custom parser) and B1 stack overflow (custom JSON encoder).

### Modules to Replace

| Custom Module | Replace With | Effort | Impact |
|---------------|-------------|--------|--------|
| `proto_adv_parse.c` (136 lines) | NimBLE `ble_hs_adv_parse_fields()` | Low | Eliminates -104 bug class, adds UUID32/128 support |
| `json_encoder.c` (163 lines) | ESP-IDF built-in `cJSON` | Low | Eliminates stack overflow risk, ~10 lines vs 163 |
| CLI (not yet implemented) | ESP-IDF `esp_console` + `argtable3` | Medium | Gets history, tab completion, argument parsing free |
| Power mgmt (not yet implemented) | ESP-IDF `esp_pm` framework | Low | Standard approach |

### Modules to Keep (thin wrappers are OK)
| Module | Why Keep |
|--------|---------|
| USB CDC wrapper | Thin wrapper over TinyUSB is standard practice |
| LittleFS wrapper | Thin wrapper over ESP-IDF LittleFS is standard |
| Filter engine | Custom business logic — no ESP-IDF equivalent |
| Lua engine | No ESP-IDF equivalent; Lua 5.4 is a design choice |
| BLE scan wrapper | Custom dedup logic on top of NimBLE scan |

### Decision Needed From User
Before continuing implementation, decide:
1. **Replace custom parser + JSON encoder with ESP-IDF built-ins?** (Recommended: yes)
2. **Use esp_console for CLI?** (Recommended: yes)
3. **Re-evaluate Lua vs MicroPython?** (Recommended: defer to later — Lua is lighter and better for LLM-generated scripts)

### Library Reuse Policy (New Rule)
Going forward, before implementing ANY module:
1. Check ESP-IDF built-in components first
2. Check ESP Component Registry (components.espressif.com)
3. Only write custom code if existing solutions can't meet a hard requirement (state why)

This policy is now added to `harness/00-global-context/project_overview.md` and `~/.qwen/QWEN.md`.
