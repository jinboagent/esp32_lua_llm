## Current Status: LIVE LLM LOOP VERIFIED ✅

### What was done
- **`.llm_env` fallback**: `llm_loop.py` reads `LLM_BASE_URL` /
  `LLM_API_KEY` / `LLM_MODEL` from a gitignored `.llm_env` next to the
  script (real env vars win). Needed because env vars set in the user's
  terminal never reach already-running shells on Windows.
- **Live field test** (DashScope `glm-5.2`, 30 deduped samples, 3148 chars):
  model produced a 1098-byte sandbox-safe script on the first try — RSSI
  gate, name/uuid interest heuristic, per-address throttle, compact
  `transform` output. Bridge accepted it; stream went 68 → 10 adv/6 s;
  clean SCRIPT STOP + SCAN STOP; exit 0.
- **Artifact**: the live-generated script saved as
  `docs/example_llm_generated.lua`.
- Docs: README + H5.1 spec document the `.llm_env` fallback.

### Friction log (lessons)
- User's terminal env vars are invisible to agent shells (process env is
  inherited at start) — hence `.llm_env`.
- Two attempts to hand-edit `.llm_env` never reached disk (unsaved buffer);
  solved with `set /p K=...` + `echo LLM_API_KEY=%K%>> .llm_env` so the
  secret never traversed chat.
