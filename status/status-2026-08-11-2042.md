## BLE connection with the PC — what we learned (live)
- While the dongle scans, the PC (bleak central) scanned back: **dongle not
  discoverable, no GATT server → cannot be connected in v1**. That is by
  design (passive scanner); today's P3 check pins this boundary as a
  regression guard. PC↔dongle connections are a **v2 feature**, test plan
  drafted (below).
- The PC can act as a deterministic BLE counterpart: WinRT advertising
  works with **manufacturer-data-only payloads** on this machine
  (Win10 19045, MediaTek adapter — `local_name` payloads fail with
  E_INVALIDARG; quirk documented in the suite). bleak 3.0.2 + winrt 3.2.1
  installed via pip.

## Key Decisions & Findings
- The 7-arg `on_adv` ABI is now proven **on device** (introspection script:
  `select('#', ...)` → 7). Any future script/test using 3 args is wrong.
- Hook effects are measurable on the stream: suppress-all ⇒ exactly 0
  lines; transform ⇒ 100 % marker injection; SCRIPT STOP ⇒ clean revert.
  These three deterministic checks replace the old "looks about right"
  manual hook testing.
- Environment quirk: Win10 BLE advertising rejects `local_name`
  (E_INVALIDARG) on this adapter — controlled-peer tests key on
  manufacturer data (id FFFF, payload `SNF AABBCC`) instead.
